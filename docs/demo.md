# Демо DiaBetrics: сценарий и чек-лист

Владелец: Dev 3. Сценарий проверен автоматической репетицией `scripts/demo_rehearsal.py`
(два прогона подряд без сбоев на ×60 и на ×30).

**История для зрителей:** ночь, Аня спит, сахар медленно падает. Бот предупреждает заранее,
Аня не отвечает — бот пишет её близкому человеку Боре. Боря связывается с Аней и нажимает кнопку.

## Кто что держит

| | Что | Аккаунт Telegram |
|---|---|---|
| Ноутбук | бот + pipeline + фейковый Nightscout | — |
| Телефон 1 | Аня — пользователь | свой аккаунт |
| Телефон 2 | Боря — доверенное лицо | **другой** аккаунт |

На обоих телефонах: включён звук уведомлений, чат с ботом закреплён, есть интернет. У ноутбука тоже
нужен интернет: бот получает сообщения из Telegram.

## Перед каждым прогоном — сброс (обязательно)

Автоматическая репетиция показала: **второй прогон на той же БД ломается на первом шаге** — бот помнит
Аню («Nightscout уже подключён»), а pipeline помнит показания и уведомления первого прогона и
молчит, пока сценарий не догонит прошлое время.

1. Остановить бота и фейковый Nightscout (Ctrl+C в обоих терминалах).
2. Удалить базу вместе со служебными файлами SQLite:
   ```bash
   rm -f data/diabetrics.db data/diabetrics.db-wal data/diabetrics.db-shm
   ```
3. На обоих телефонах: в чате с ботом «Очистить историю» — иначе останутся кнопки прошлого прогона.
4. Проверить логику без телефонов (около 30 секунд), должно быть «все прогоны без сбоев ✓»:
   ```bash
   python scripts/demo_rehearsal.py --runs 1
   ```

`.env` на ноутбуке: `BOT_TOKEN=<токен демо-бота>`, `CLOCK=nightscout`, `POLL_SECONDS=2`.

## Фаза 1 — подготовка (до выхода на сцену, ~3 минуты)

Фейковый Nightscout в **реальном** времени с 23:00 — сахар спокойный, уведомлений не будет.

1. Терминал 1:
   ```bash
   python fake_cgm/fake_cgm.py --serve --scenario night_hypo --speed 1 --skip 0 --token secret
   ```
2. Терминал 2:
   ```bash
   python -m app.main
   ```
3. Телефон 1 (Аня): `/start` → `http://localhost:1337` → `secret` → «Москва (UTC+3)».
   Адрес `localhost` правильный: его открывает бот на ноутбуке, а не телефон.
4. Телефон 1: `/trusted` → переслать ссылку Боре.
5. Телефон 2 (Боря): открыть ссылку → «Запустить». Обоим придёт подтверждение.

Почему так: время фейкового Nightscout идёт с момента его запуска. Если сразу запустить его ускоренным,
гипо случится раньше, чем Аня успеет подключиться.

## Фаза 2 — на сцене (~1 минута)

1. Терминал 1: Ctrl+C и сразу запустить ускоренным с 01:45. **Бота не трогать.**
   ```bash
   python fake_cgm/fake_cgm.py --serve --scenario night_hypo --speed 30 --skip 165 --token secret
   ```
2. Дальше всё происходит само. Время — от перезапуска, по репетиции на ×30:

| Когда | Где | Что видно | Что сказать |
|---|---|---|---|
| сразу | Телефон 1 | `/now`: 4.1 ↘, «через 20 мин ~3.0», «🌙 Ночной по расписанию, до 07:00» | «Ночь, сахар 4.1 и падает. Ночной режим включился сам» |
| ~2 с | Телефон 1 | 🔴 «Сахар падает: через 20 минут может быть 3.0», кнопка «Я в порядке» | «Бот предупреждает заранее — по прогнозу» |
| ~10 с | Телефон 1 | 🔴 «Низкий сахар: 3.9» — ночью сразу критическое | «Ночью низкий сахар будит» |
| ~12 с | Телефон 1 | повтор первого уведомления | «Аня спит и не отвечает — повтор» |
| ~23 с | Телефон 2 | «🔴 Аня не отвечает уже 10 мин. Сахар сейчас… Связались, всё в порядке» | «Через 10 минут бот пишет близкому» |
| по нажатию | Телефон 2 → 1 | кнопки гаснут, Ане: «✅ Боря подтверждает: всё в порядке» | «Боря позвонил Ане — цепочка закрыта» |

Через ~10 с после первого Боре придёт второе сообщение — уже про сам низкий сахар (это отдельное
уведомление). Его тоже можно подтвердить или сказать: «Аня проснулась» — и нажать «Я в порядке»
на Телефоне 1.

3. Если есть время: `/mode`, `/settings`, `/graph` (кнопки 3 / 6 / 24 ч), фото еды → КБЖУ и кнопка
   «Включить „После еды“».

Нужно больше пауз для рассказа — `--speed 20`; быстрее — `--speed 60` и `POLL_SECONDS=1`.

## Вариант на сервере (docker compose)

В боте адрес `http://fake-ns:1337`, токен — `FAKE_NS_TOKEN` (по умолчанию `secret`).

```bash
SPEED=1 SKIP=0 docker compose --profile demo up -d --force-recreate fake-ns    # фаза 1
SPEED=30 SKIP=165 docker compose --profile demo up -d --force-recreate fake-ns  # фаза 2
```
Сброс перед прогоном: `docker compose stop bot`, удалить `data/diabetrics.db*`, `docker compose up -d bot`.
Внимание: это удаляет всех пользователей на сервере.

## Если что-то пошло не так на сцене

| Симптом | Причина | Что делать |
|---|---|---|
| в фазе 1 `/start` отвечает «уже подключён» | не сброшена БД | остановить всё, сделать сброс, начать фазу 1 заново |
| уведомлений нет 30+ секунд | бот не видит fake-NS или `CLOCK` не `nightscout` | смотреть терминал 2: строки `pipeline: user_id=… +N показаний` |
| Боре ничего не пришло | Боря не принял приглашение | Телефон 1: `/trusted` — должно быть «Доверенные лица: Боря» |
| совсем всё плохо | — | запасной слайд со скриншотами; на ноутбуке `python scripts/demo_rehearsal.py --runs 1 -v` показывает весь сценарий в терминале |
